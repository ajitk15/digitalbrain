Digital Brain · Knowledge

From documents to a cited answer

Digital Brain turns an application's documents and tickets into a knowledge graph, then answers questions from it. Every answer points back to the exact line it came from. Below are the two journeys, with one small health-insurance example carried all the way through.

The example: MRI claims paid without prior authorization

A health insurer's claims team has three sources in Digital Brain. A plan rule says an MRI needs prior authorization before it is paid. A Jira ticket reports that the claims system is paying MRI claims anyway. A runbook says what to do while that is being fixed.

1. Building the knowledge graph

Sources become a graph in four stages. The structure is built for free whenever a source changes. AI enrichment runs only when someone asks for it, and nothing reaches Chat until an owner publishes it.

Collect

Bring sources in

Uploads, links, and connectors for Jira, GitHub, ServiceNow and SharePoint. A connector can re-import on a schedule.

CARE-412 arrives with its status inside the text, so "In Progress → Done" counts as a change.

Convert & fingerprint

Word and PDF files become plain text offline, with no internet access. Each source gets a fingerprint of its exact content.

Claims policy.docx → a table with BR-05, plus a fingerprint like 3f9a…c21.

→

Build structure

Automatic · free

One node per fact

Each source, each table row and each "field: value" becomes a node. Each link keeps the line it was read from.

BR-05 → Requirement: An MRI needs prior authorization…

Same value, one node

The same value under the same column in two documents becomes one shared node, which joins the documents.

"Service: claims-service" in two tables would link them.

→

Enrich with AI

Only when requested · within the monthly budget

Propose typed links

The model reads new or changed sources only. It can use eight types (Ticket, Requirement, Runbook…) and twelve relations (affects, violates, covers…).

CARE-412 violates BR-05, quoting "This breaks BR-05"

Keep only what is quoted

Every proposed link must quote its source word for word. A link with no matching line is refused.

Kept "claims-service approves MRI claims"
Refused "CARE-412 fixes billing", no such line

quoted links only

→

Draft & publish

Save a version and test it

Every run saves a draft version. The owner's test questions are scored against it automatically, with no AI and no charge.

v3 · draft: 15 of 16 test questions find their source.

Publish

An owner publishes a version. Chat and Code Factory only ever answer from the published one, never a draft.

v3 published → Chat answers from v3.

2. Answering a question

A question passes through five stages. Finding and ranking cost nothing. A model is called only to write the answer, and only after every piece of evidence has been checked against the live source.

Ask

Receive the question

From Chat, from the API, or from Code Factory working on a ticket.

"Why are MRI claims being paid without prior authorization, and what do we do?"

→

Find & rank

No AI · free

Match words and references

Each question word is matched in its root form, while an ID such as BR-05 stays whole. Each source's best passage comes before any source's second one.

"authorization", "MRI", "claims" → CARE-412 and BR-05

Walk the graph

From the best matches, follow up to two hops of typed links to find what a keyword search would miss. These finds come after the direct matches.

CARE-412 → affects → claims-service ← covers ← Claims runbook

→

Verify

Check every citation

Each piece of evidence must still be active, have an unchanged fingerprint, and its quote must still appear in the source.

✓ Claims runbook is unchanged since v3

Check who is asking

A source marked restricted is never sent to AI. A Jira record is cited only to people Jira lets open it.

✓ The asker can open CARE-412
✗ Member appeals.xlsx is restricted, so it is left out

what the model claims is not evidence

→

Answer

Write from checked evidence

The model writes only from the verified passages and numbers its citations. The answer is shown as plain text.

CARE-412 tracks it: claims-service approves MRI claims with no prior authorization on file[1], which breaks rule BR-05[2]. Until it is fixed, hold MRI claims for review. The Claims Team owns the service[3].

[1] CARE-412[2] Claims policy · BR-05[3] Claims runbook · claims-service row
→

Measure & improve

Keep score

The Quality tab shows four plain answers per version. Test questions are scored on every version, a scorecard runs on every change, and a drift check runs whenever the model changes.

Add "Who owns claims-service?" as a test question, and every later version is checked against it.

# Digital Brain — graph generation and security

A 22-slide offline presentation for college students, application users, and a project demonstration. Prepared on 12 October 2026 from the repository implementation. Examples use synthetic DEMO identifiers.

## Present

Open **index.html** in a desktop browser. Use the chapter list, Previous/Next buttons, or arrow keys. **N** shows speaker notes; **T** shows technical detail and repository references. Fullscreen uses the browser's standard fullscreen API. Print / PDF uses the browser's print dialog; printed output includes all slides, and optionally any enabled notes.

Allow 25–30 minutes for the explanation and 5 minutes for the prepared application demo on slide 22. Read **presenter-guide.md** for the full speaking script, technical explanation, and code references. Slides 2–5 explain the three graph modules, Graphify's two roles, the Graph RAG flow/chat modes, and the technology stack. **technology-map.md** contains the complete reference.

The slides contain two educational simulations: relationship proposal validation and answer-time citation checks. These do not call providers or modify application data.

## Explore the diagrams

- **generation.html**: the combined diagram-and-table page. Its numbered boxes show technologies and purposes rather than script names. A detailed table covers all 12 boxes: the key libraries/algorithms, purpose and reason, how each stage works, where it runs, and its limits/security boundary. Use **Every box explained** to jump to the table. Graphify's theme and code-analysis roles are distinct from the application's custom Knowledge graph and Graph RAG flow.
- **generation-diagram.html**: the independently validated interactive diagram component, embedded in generation.html and available through **Open diagram fullscreen**. The local Graphify boundary explicitly states that these paths make no graphify.net service calls. Its source is **generation.architecture.json**. The page/table content is generated by **build_generation_page.py**, with its 12-row data recorded in **generation-boxes.json**.
- **pipeline.html**: the simplest overview, for anyone new to the platform. One page in the style of a four-stage RAG diagram: how the graph is built (Collect, Build structure, Enrich with AI, Draft & publish) and how a question is answered (Ask, Find & rank, Verify, Answer, Measure & improve). One illustrative health-insurance example runs through every card: MRI claims paid without prior authorization (policy rule BR-05, Jira ticket CARE-412, a claims runbook), with a drawing of the graph it produces. Light and dark, and stacks to one column on a phone. It loads the Figtree and JetBrains Mono fonts from Google Fonts when online and falls back to system fonts offline.
- **security.html**: user/application authorization, source eligibility, answer-time citation verification.

Both diagrams are standalone Archify viewers with light/dark modes, focus/search, presentation controls, and export features. The generation map uses the architecture renderer; the security map uses the workflow renderer. Main presentation and diagram files work offline and load no external fonts or assets. Open the diagram links separately for detailed exploration.

## Evidence and boundaries

The guide and **source-map.json** point to the repository functions supporting the explanations. These source links work inside the repository; source files are not included in the portable ZIP. Statements describe implemented behavior, not a production infrastructure audit or security/compliance certification.

The permission boundary is explicitly covered: optional Jira source lists protect answer citations and answer-tool evidence, while source pages and graph exploration still use application access. Graph generation uses application-level non-restricted sources, rather than a separate source-ACL-filtered graph per viewer. Provider data retention, encryption at rest, and deployment security require separate evidence.

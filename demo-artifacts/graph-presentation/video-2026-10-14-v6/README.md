# CarePath: one file becomes connected knowledge

Four-minute version 6, with new CarePath narration by Microsoft Heera (en-IN), progressive circular graph, left step rail and a compact subtitle strip. Earlier versions remain available separately.

## Source evidence

Actual project files from demo-artifacts/docs:
- 01-requirements/user-stories.docx: US-08, Track a referral (FR-08).
- 02-design/architecture.html: component row connects FR-08 to domain/referral_state.py.
- 04-test/traceability-matrix.xlsx: FR-08 row names TestLifecycleMap and other tests.

MarkItDown converted all three local files. source-content.json and source-1.md through source-3.md preserve the converted content. revalidate.py runs the project structural builder, evidence judge and enrichment merger with prepared proposals. It verified 4 business entities and 3 business relationships; the full converted structural graph has 459 nodes and 475 edges. The animation intentionally shows a selected, readable subset.

The graph begins with one source, adds heading and text nodes, then US-08 and FR-08. The two subsequent files add source, code and test nodes around FR-08. Validation changes proposal status and preserves evidence; it does not invent extra business facts. Search preparation adds an illustrated vector index beside the graph. Displayed vector numbers, question matching and theme labels are illustrations, not executed provider results. Theme grouping in the revalidation uses the actual graph functions.

This is a teaching animation, not a recorded live UI session. AI outputs are prepared examples verified against exact source quotes. No external AI, embedding, publication, or retrieval request was made. CarePath technology described by source documents is distinct from the Django Digital Brain pipeline processing them.

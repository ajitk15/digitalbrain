Presenter notes

Technical detail

03 / 22 · Where Graphify fits

Graphify has two specific jobs here

The installed Python distribution is graphifyy; application code imports it as graphify. Its use is local analysis and clustering in these paths.

Code Graph: Tree-sitter extraction

  1. Copy bounded source texts into scratch storage.
  2. Call graphify.extract.extract.
  3. Map symbols and cross-file links into Code Graph records.

Calls, imports, and inheritance supplement the native analyzer.

Knowledge graph: Leiden themes

  1. Project stored nodes and edges into NetworkX.
  2. Call graphify.cluster.cluster.
  3. Name communities with their hub node and compute cohesion.

Themes are shared by Quality and canvas colouring.

Graphify’s model-based semantic extraction pass is not invoked by the Code Graph adapter.

Presenter notes

Say the package and import names distinctly: install graphifyy, import graphify. The Code Graph uses Graphify's Tree-sitter pass on already-read source text in two temporary directories. It does not hand Graphify the entire checkout or git metadata. Knowledge graph themes use a different Graphify module for clustering. Clustering groups existing links; it does not create new facts or call the extraction model.

Technical detail

  • code_graph_graphify.analyse calls graphify.extract.extract with parallel=False, maps accepted relation kinds, and keeps scratch sources/cache separate from the checkout.
  • The native analyzer keeps Python and JS-family symbol/import handling; Graphify supplies additional language symbols and cross-file call/inheritance edges. Failure marks the code snapshot partial rather than discarding all native results.
  • graph_quality.communities calls NetworkX Graph, graphify.cluster.cluster, and label_communities_by_hub; themes also calls cohesion_score. The Leiden backend dependency is graspologic-native.
  • Observed local versions on 12 October 2026: graphifyy 0.9.67, NetworkX 3.7, graspologic-native 1.3.1. These are environment observations, not permanent version guarantees.

Presenter notes

RAG means retrieval-augmented generation. Here Graph RAG is the application's own graph-backed retrieval and answer flow. It does not mean that Microsoft GraphRAG, Neo4j, or LangChain is powering this code path. A structural-only graph can still support Graph answer mode if graph retrieval is configured; semantic enrichment and answer generation are different settings. 06 / 22 · Graph basics

A graph is a set of things and relationships

A node names a thing. An edge says how two things connect. Provenance explains where that edge came from.

Presenter notes

Read this aloud: ticket DEMO-101 violates requirement REQ-7; REQ-7 is implemented in a code file. This is a teaching example of allowed types and relationships. An arrow does not prove the implementation is correct. It records a claim backed by a source quote. Distinguish the real-world fact from the graph's representation of the source's statement.

Technical detail

  • Nodes have stable application-scoped IDs. Structural IDs derive from SHA-256 over application namespace, kind, and identity.
  • Edges retain source and target IDs, relation, knowledge_id, digest, line, and evidence. AI-derived relationship edges also carry inferred=True.
  • The graph is persisted as JSON data in GraphRevision in the relational database; this implementation does not require a dedicated graph database.

08 / 22 · Intake

Files become local, bounded Markdown

The generator reads normalized knowledge entries. It does not ask an AI model to open arbitrary uploaded files.

1Store privately

Application-specific quarantine file.

2Check integrity

Stored size and SHA-256 must match.

3Scan

Required in production; fail closed.

4Convert

Local MarkItDown subprocess.

5Record

Save text, digest, and scan findings.

Presenter notes

Demonstrate an uploaded text document moving through the Sources screen. The original bytes are stored privately. Before conversion the code checks whether those bytes still match the recorded hash. Production requires a working scanner with current signatures. Conversion gets a local stream, not a URL, and plugins are disabled. Image-only PDFs need OCR; this pipeline reports that limitation rather than pretending it extracted the page.

Technical detail

  • Upload limit: 20 MiB. Conversion timeout: 45 seconds. Maximum accepted Markdown: 1,000,000 characters. Archive member/expanded-size and PDF page/encryption checks are implemented.
  • ClamAV invocation has a 30-second timeout and rejects stale signatures; scanner failures leave the stored file private.
  • The converter disables plugins and patches Python socket connect/connect_ex. This is a bounded subprocess, not a claim of complete OS/container isolation.
  • KnowledgeEntry stores a content SHA-256 and suggested personal-data findings. Sensitivity classification remains a person's decision.

11 / 22 · Validation

Six questions before an AI edge is kept

These checks are code, not just instructions in a prompt.

01

Valid shape?

Required fields must be nonempty strings.

02

Known source?

source_id must name a source supplied to extraction.

03

Real quote?

A bounded exact quote must occur in that source.

04

Named entities?

Subject and object must be present under the naming rules.

05

Allowed relationship?

Subject type, relation, and object type must fit the ontology.

06

Room in the graph?

Duplicates are removed and node limits are enforced.

Presenter notes

Ask students why each check exists. An unknown source is a provenance failure; an absent quote is unsupported evidence; a bad type pair is an invalid relationship in our vocabulary. The subject has one controlled exception: a Ticket, Runbook, Incident, or Change may name the source itself by its verified title or key. The object still has to appear in the quote. Quote matching is case-sensitive; entity presence checks are case-folded.

Technical detail

  • judge returns either canonical (subject type, relation, object type), or an explicit rejection reason. Maximum quote length is 300 characters; subject/relation/object names are bounded to 120 characters.
  • Rejection counts and reasons are stored in quality data. A discarded proposal is not silently presented as a valid edge.
  • Exact-quote presence is not a semantic entailment proof: polarity, ambiguity, and incorrect statements in the source still require review.

A small vocabulary makes paths understandable

Consistent types and relationship names let a ticket connect to a requirement and then to code.

Presenter notes

An ontology is a shared vocabulary, like a course glossary with grammar rules. We do not allow any relation between any two types. The same registry writes the extraction prompt and checks the response. Name merging is conservative: same type and normalized or sufficiently similar word-by-word names, with numeric identifiers preserved. Similar names are a heuristic, not absolute proof of identity.

Technical detail

  • ontology.py defines eight types and the canonical relationship registry with allowed endpoint types and aliases.
  • Normalization handles case, accents, punctuation, separators, and a leading 'the'. Matching may stem words or accept long near-identical words using Jaro-Winkler ≥0.93; shorter words and numbers have stricter rules.
  • Merged entities preserve aliases and contributing source IDs. Every edge keeps its own provenance and remains independently checked.

13 / 22 · Versioning

Reuse unchanged work; save a new draft

Digests detect changed content. Fingerprints describe the graph-generation input. A saved revision is a stable snapshot.

1Compare

Source IDs + digests + configuration + limits.

2Reuse

Keep eligible prior AI extraction for unchanged sources.

3Build

Extract new or changed sources within run limits.

4Commit

Recheck fingerprint in a transaction.

5Measure

Run retrieval benchmark after the save.

Presenter notes

Explain the difference between a digest and a fingerprint. A source digest describes its content; the generation fingerprint includes the source set and generation settings. Rebuilding a ready unchanged graph is a no-op. AI reuse requires matching source ID and digest under the same ontology. The transaction checks whether the input changed while the worker was running, so it does not commit a snapshot based on outdated input.

Technical detail

  • KnowledgeGraph holds the current build state. GraphRevision saves numbered data/quality, provider/model, and fingerprint for that application.
  • reusable reads the latest AI revision with matching ontology, retains completely processed unchanged sources, and carries forward their entity nodes and edges.
  • The current reuse check is based on source ID/digest and ontology; it is not a guarantee that every model or prompt change automatically re-extracts all unchanged sources.
  • The standard after-save benchmark reads stored information and calls no model. Benchmark failure cannot roll back a successfully saved revision.

14 / 22 · Search

Embeddings choose where to look

Word matching and optional meaning matching rank candidate evidence. A vector itself is never a citation.

01

Word search

BM25 rewards informative query terms in relationship text.

02

Meaning search

Optional embeddings find nearby texts even when wording differs.

Hybrid retrieval

  1. Rank words and optional vector candidates.
  2. Fuse their rankings.
  3. Expand along typed graph relationships.
  4. Verify live sources before citing.
Ranking decides what to check first.
Verification decides what can be cited.

Presenter notes

Use two differently worded questions to explain meaning search, without promising that it will always find the answer. This implementation uses optional OpenAI embeddings, 512-dimensional unit vectors, cosine similarity, and reciprocal rank fusion. AI generation can index relationships and passages if embeddings are configured. Search can still use words when no new embeddings are available.

Technical detail

  • Embeddings are opt-in and content-addressed, so stored unchanged texts are reused. Question embeddings can incur a provider request when a question is asked.
  • Retrieval uses BM25 covering ranks, optional nearest-vector candidates, and bounded typed multi-hop/one-hop expansion. Direct candidates are considered ahead of multi-hop finds.
  • The in-process NumPy search is exact cosine similarity over stored vectors; this is not a claim that a managed vector database is deployed.
  • If embedding indexing fails, graph relationships can still be saved with a warning; word ranking and available existing vectors remain usable.

19 / 22 · Input and browser safety

Treat files, links, and model output as untrusted

Bounded processing and server-enforced checks reduce exposure; they do not make arbitrary content harmless.

01

Files

Private storage, integrity checks, production malware scanning, bounded conversion.

02

Links

HTTP(S) only, DNS/IP checks, pinned destinations, no automatic redirects.

03

Browser

CSRF protection, clickjacking denial, escaped rendering, restrictive response policy.

04

Sessions

Argon2 password hashing, login throttling, private responses marked no-store.

Presenter notes

Explain SSRF as a server being tricked into fetching a private address. The fetcher checks all resolved addresses and pins the connection to the checked address, while preserving hostname certificate verification for HTTPS. Operators may explicitly allow internal hosts. Prompt injection is handled as untrusted source text plus validation, but a prompt instruction is not a complete defense by itself. Show security settings as implemented code, not as a certification claim.

Technical detail

  • Link fetches are bounded to 8 MiB and 20 seconds, with a 5-second per-address connection timeout. Private/reserved destinations are blocked unless the operator allowlists that hostname.
  • Production enables HTTPS redirect, secure session/CSRF cookies, HSTS, and PostgreSQL verify-full TLS. These require a correctly configured deployment; the local HTTP demo is not evidence of production TLS.
  • Conversion is not a full OS sandbox. Malware scanning depends on installed scanner/signatures. Automated safeguard tests are useful probes, not proof against every attack.

Presenter notes

This is the most important honesty slide. An answer permission boundary is narrower than an explorer confidentiality boundary. An application member may still see imported records in the Sources and graph screens. Restricted means excluded from AI use and citations, not deleted from storage or hidden from application members. A published version is not a secure erase mechanism. If your audience asks about regulated deployment, explain that legal, contractual, infrastructure, and operational checks are separate work.

Technical detail

  • permissions.py documents the UI/explorer boundary and supports only Jira for optional source permission enforcement. The normal recheck window is 24 hours, performed during sync; this is not an immediate live-per-question Jira ACL query.
  • Generation selects application-level active, non-restricted sources; it does not build a separate permission-filtered graph for each viewer. Answer-time permission checks must not be described as full source ACL isolation of generation/enrichment or the explorer.
  • sensitivity.scan checks a bounded set of patterns over up to 200,000 characters and leaves labeling to a human.
  • The corpus-wide benchmark's EVERYONE viewer deliberately ignores viewer-specific permission lists to measure retrieval; it does not prove that a particular end user may access every benchmark source.

Presenter notes

Tell the audience that bigger does not mean complete. A source can be read while some of its rows were omitted. That is why both source coverage and content coverage matter. The current limits are implementation choices, not throughput measurements or an SLA. A stalled build is treated as interrupted after its inactivity window; a previous published version is not automatically erased by a failed new build.

Technical detail

  • The stall window is derived as extraction timeout / 60 + 5 minutes, currently 15 minutes. Duplicate generation claims are refused while a run is live.
  • Embedding failure is nonfatal and warns. A budget interruption may retain partial AI work when there is already usable extraction; initial failure can stop the run.
  • The graph explorer uses a browser canvas force simulation. Layout distance and cluster appearance do not prove relationship strength or causality.

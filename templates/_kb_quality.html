{{ health.nodes }}Nodes

One node per source, one per table row, and one per distinct field-and-value pair; the same value in two sources collapses into a single node. Capped at 6,000. To improve: This is size, not quality. It grows with more sources and richer tables. Sitting exactly at the cap means the graph is being trimmed, and a note below will say so.

{{ health.edges }}Relationships

One relationship from each source to each of its rows, and one from each row to each non-empty cell, labelled with that column’s header. AI enrichment adds more. To improve: Fill blank cells and give every table a real header row — a blank cell produces no relationship, and a missing header names the relationship “column 3”.

{{ health.cross_document }}Cross-doc linksshared between documents

Value nodes reached from two or more different sources. A value node belongs to no single source, so identical text under an identical column header becomes one shared node — the only genuine cross-document join the structural graph makes. To improve: Spell shared values the same way everywhere and reuse column headers across documents. “NODE1” and “Node 1” stay two separate nodes and join nothing.

{{ health.components }}Componentslargest {{ health.largest_percent }}%

Disconnected pieces of the graph, with the share of nodes in the biggest one. Flagged above one piece per 20 nodes, or when the largest holds under 60%. To improve: Shared values are what join pieces together, so the fix is the same as for cross-doc links: consistent column headers and consistent value spelling across sources.

{{ health.orphan_percent }}%Orphans{{ health.orphans }} unconnected

The share of nodes that appear in no relationship at all. Flagged above 15%. To improve: Orphans are usually prose headings that became a node but joined nothing. Put the facts in tables with headers, so each row links to its own values.

{{ health.evidence_percent }}%Evidencedquote their source

The share of relationships that carry a quoted line from their source. To improve: Anything below 100% cannot be cited in an answer. Regenerate the graph after correcting the source, rather than editing the graph.

{{ graph.quality.included_rows }} / {{ graph.quality.table_rows }}Table rowsrepresented in the graph

Every Markdown table row found under a header row, and how many became records. The two differ only when a limit is reached: 2,000 rows per source, or 6,000 nodes in total. To improve: If the numbers differ, split the source into smaller documents. Nothing else lowers it — the limits are fixed.

{{ graph.quality.empty_cells }}Empty cells

Blank cells inside the table rows counted above. To improve: Each blank produces no value node and no relationship, so the row is represented more thinly than it looks. Fill them in the source document, or drop a column that is genuinely unused.

{{ graph.quality.duplicate_rows }}Duplicate rows

Rows whose cells exactly repeat an earlier row within the same source. They are counted, never dropped. To improve: De-duplicate in the source document. A repeat contributes no new values but does add another record node.

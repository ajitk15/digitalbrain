{% comment %}The kinds of source first, from `source_kinds.KINDS` (`workspace.source_tabs`) - Documents, Code Repos, Tickets - then Graph, Quality, Versions. Each kind is gated on its own feature and condition there: Code Repos on Code Graph, the rest on Knowledge, so an application with only one of them still reaches what it has; Tickets only when the application imports tickets, with no count, which read as a problem whenever it was 0. A kind's tab is current on every page in its `views`: Code Repos on Structure, Reviews, Documentation and a file too, because those read one of its repositories. Adding a kind is a registry entry, never an edit here. The benchmark is not a tab: it scores versions, so it opens from the Versions table and from Quality's "Finds the right source" card, as a popup over either. The status strip above the tabs (`_knowledge_status.html`) says what answers and what is waiting, on every page that draws these tabs.{% endcomment %}{% load icons workspace %}{% knowledge_features application as has %}{% source_tabs application as kinds %}

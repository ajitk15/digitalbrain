2. Retrieval / Answering Pipeline

Understand the question, gather candidates from passages and the graph, filter and rerank, then answer — only with citations that verify.

User question
"Is patient consent checked before a FHIR export?"

1. Query understanding

  • Split into search terms; filler words dropped, word endings normalised
  • IDs kept whole — BR-05, C-09, CARE-401
▼

2. Passage retrieval

  • Full-text search over passages
  • Most question terms first, then BM25
  • Every source's best passage first

3. Graph retrieval

  • Matches relationships in the published graph
  • Walks up to two hops, after direct matches
  • Code Factory follows IDs a ticket names
▼

4. Fuse, filter & rerank

  • Meaning matches merged with keyword matches
  • Only what the asker may see — Jira permissions, fail closed
  • Restricted sources never read; AI rerank only reorders
▼

5. Verify & generate

  • Each citation re-checked: source active, unchanged, quote still there
  • Claude or OpenAI writes it through the AI gateway: budget, receipt
  • Streamed live; resumes after a dropped connection

Answer with sources

  • Plain-language answer with numbered citations you can open

4. Organization Hierarchy & Role-Based Access

Deny by default: access is an explicit grant on one application, re-checked on every request and every AI tool call. Administering the tree never grants access to what is in it.

Four levels under the platform

PlatformPlatform administratorsConsole, people, sign-in settings, operations; can disable or delete any level. Never opens an application without a grant.
OrganizationMembers · organization administratorsApprove invitations, add members, create portfolios, products and applications.
PortfolioGroups productsA business area of the organization.
ProductGroups applicationsOne product, with its applications for engineering, operations or both.
ApplicationGrants: owner · contributor · viewerKnowledge, features, ontology pack, connectors, credentials, AI budget. Its own data, isolated in the database.
Disable is reversible. Each level has its own switch; an application is live only while all four are on. Queued work is stopped; running work finishes.
Delete is deliberate. Only a disabled level, with its name typed, and nothing in flight. Audit events and AI receipts outlive it.

5. Identity, User Management & Security

Microsoft Entra ID signs people in and provisions accounts, but grants nothing: every grant is made, audited and reviewed here. User ID and password sign-in always works, with or without Microsoft.

Single sign-on — OpenID Connect with PKCE

SCIM provisioning (off by default): Entra creates accounts with no password, membership or grant, updates name and email, and deactivates on unassign. Never deletes, refuses groups, never touches a platform administrator.
Password sign-in always works, with an optional authenticator app. Groups and app roles from Entra are never read, so the directory cannot widen access.

User management — join, work, leave

Join

  1. Owner invitesA member of the organization is granted at once; anyone else waits
  2. Org admin approvesThe inviter's rights are checked again at approval
  3. One-time link, 72 hoursThe person sets their own password — never sent to them

Work

  1. Optional authenticator appSix-digit codes, each used once; ten recovery codes
  2. Access can end on a dateViewer and contributor grants expire; an owner's never does
  3. Owners review accessEvery 90 days each owner confirms who has access

Leave

  1. Offboarding names a successorOwnership, administration and connectors move to them
  2. Disabled and tokens revokedAutomatic AI refresh is stopped, not handed on
  3. Directory unassigns (SCIM)Account deactivated; sessions and API tokens end
Every step is an audit event naming who did it. Automatic actions run as named non-login accounts — access-expiry, entra-provisioning — so nothing is misattributed.

Security built in

Sign-in
  • Passwords hashed with Argon2, at least 14 characters
  • Locked for 15 minutes after 5 failures, by account and address
  • 30-minute sessions; HttpOnly, Secure cookies; HSTS for a year
Browser
  • Strict Content Security Policy: no inline script, no other origins
  • Cannot be framed; camera, microphone and location off
  • AI text is escaped, never rendered as Markdown or links
API & MCP
  • Bearer token only, stored as a SHA-256 digest
  • 120 requests a minute per token
  • A token is its user: revoke the grant and the token stops
Data isolation
  • PostgreSQL row security binds each connection to one application
  • Runs as a least-privilege role: rows only, no schema changes
  • Restricted sources never reach a model; health IDs masked first
Secrets
  • One file per provider per application, owner-only
  • Never in the database, logs, audit trail or browser
  • A typed credential never overrides an operator's mounted one
Content & network
  • Every upload virus-scanned; conversion runs with no network
  • Outbound fetches refuse private addresses and pin the address
  • Parsers and AI coding agents run in a locked-down sandbox
Accountability
  • Audit trail kept at least six years (HIPAA)
  • A receipt for every paid AI call, against a monthly budget
  • Traces and metrics carry ids and timings only, never content
Answers
  • Every citation re-checked against its live source
  • Source-system permissions follow the asker, failing closed
  • Scorecard release gate: leak counts and HIPAA probes must match

9. Example — Retrieval and Final Answer

User question

"Is patient consent checked before a FHIR export?"

Retrieved subgraph & passages (partial)
  • • CARE-401 → violates → BR-05  ·  BR-05 → required by → C-09
  • • Traceability matrix: BR-05 "Partially covered"; no test joins consent to export (T-03)
  • • Risk register: R-01 scored 20 — escalated to the board
Final answer (generated, every claim cited)

No. BR-05 requires consent decisions to be honoured before a record leaves the organisation[1], but the export path does not consult the consent record — CARE-401 is open at Highest[2]. No test joins consent to export (T-03)[3], and the risk register scores this R-01 at 20, escalated[4].

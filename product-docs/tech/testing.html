Testing gates and the scorecard

Nothing is done until five gates are clean. The fifth - the scorecard - measures whether answers, citations, cost control and safeguards got worse, so a change that weakens retrieval fails the build like a broken test.

.venv/Scripts/ruff.exe check digitalbrain platform_core scripts manage.py
.venv/Scripts/python.exe manage.py makemigrations --check --dry-run
.venv/Scripts/python.exe manage.py test
.venv/Scripts/python.exe scripts/production_preflight.py
.venv/Scripts/python.exe manage.py scorecard --check

(On Linux, .venv/bin/.)

The test suite

  • Test runner (digitalbrain/test_runner.py) blanks Redis, the scanner, OTel, the bucket, the web server choice and the shared connector folder, so a file on the developer's machine cannot change what "not set" means. It turns the Claude Messages path off; a test of that path turns it on.
  • Browser tests (test_browser.py): Playwright drives the installed Chrome against a live test server with the model patched out, so the JavaScript runs for real. They exist because a script error once made every in-place progress update throw for a day while every HTML test passed. They skip and say why without Playwright or Chrome, or with DIGITAL_BRAIN_BROWSER_TESTS=0. They wait on selectors, never wait_for_function - that evaluates a string, and the CSP refuses it.
  • Pinned invariants: the CSP string (test_security), tenancy coverage of every table (test_tenancy), expand/contract migrations (test_migration_job), shared-lane races (test_shared_lanes), role capabilities (test_access_review), SLO rules vs registry (test_slo), environment variables botocore and the Anthropic SDK would read (test_originals, test_claude_messages), managed credentials (test_managed_credentials).
  • No test makes a real provider call. OpenAI runs through the real Agents SDK over a mocked HTTP transport; Claude's query is replaced. The working notes list what has been verified live and what has not.

The scorecard

platform_core/scorecard.py builds its own workspace from files in the repository - the CarePath documents through the real extractor, the Jira export through the real Jira connector code, benchmarks/*.json - in a throwaway database with stable ids, and calls no model. --check fails on any score worse than benchmarks/baseline.json past its tolerance; leak counts and safeguard probes must match exactly.

Technical

Architecture

Digital Brain is one Django 5.2 / Python 3.12 codebase, server-rendered with no JavaScript build step, that runs as up to four roles - web, worker, sandbox (a locked-down worker) and a one-shot migrate - over PostgreSQL, Redis, a ClamAV daemon and an object store. Everything below is drawn from the code and the Compose files.

System context

Who and what the platform talks to. Every outbound arrow carries a credential that belongs to one application, read from a file, never from the database.

Containers

The scaled deployment (docker-compose.yaml + docker-compose.scale.yaml). The single-container deployment collapses web, worker, sandbox and migrate into one app container with role all; everything else is the same.

Still not sandboxed, and the code says so: chat on Claude starts the CLI on the web container's stream thread, and every container still mounts the whole secrets volume, the owner's database password included.

A page request

A streamed chat answer

  • The answer thread is the only writer. The stream generator does no database work at all, so a Stop that races completion is safe: completion is a guarded update of a row still marked streaming.
  • With Redis an answer outlives its connection. A dropped connection resumes from Last-Event-ID on any web process; a second tab follows the same answer. A reader that finds events but no live owner closes the answer out once as interrupted - it is never started again, so nothing is paid for twice.
  • Under uvicorn a reader holds no thread. digitalbrain/asgi.py routes only the two stream routes to Django's ASGI handler (sharing 8 thread lanes); every other request goes to the same WSGI app in a bounded pool, so middleware and the CSP are unchanged. Measured on the development machine: waitress accepted 12 concurrent readers; uvicorn held 100 with every reader receiving, so 100 is the cap and reader 101 gets a 503 for another replica to serve.
  • The browser never renders model Markdown. Streamed words are inserted as text; the finished message is replaced by HTML the server rendered through one escaping filter that produces no links.

Background work

Background work is asked for, never scanned for: the cost grows with work, not with the number of applications. A rolled-back change takes its job with it. Details in Workers, lanes and jobs.

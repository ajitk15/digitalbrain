Deployment strategies

One image and one codebase run in five shapes, from a laptop with no services to a managed cloud. They differ in where the services live and how many processes serve - never in what the platform checks. Production rules are the same everywhere production mode is on.

What is the same everywhere

One image

Dockerfile targets runtime (production) and demo (adds the CarePath source, a test environment, Playwright and Chromium). User brain, uid 10001; tini as PID 1; port 8000.

Four roles

DIGITAL_BRAIN_ROLE = all, web, worker or migrate. Any shape is a choice of which containers run which role.

Secrets are files

Mounted read-only at /run/secrets, mode 0600 owned by uid 10001. Browser-managed credentials in a separate writable volume.

Migrations under a lock

apply_migrations as the owner, creating the runtime role; everyone else waits. Each migration is safe for the previous release (expand, then contract).

Checked at start

manage.py check --deploy --fail-level WARNING on every container start; load_config refuses unsafe settings.

Health

HTTP health check with an allowed Host header for web; queue_status --check --lanes for workers.

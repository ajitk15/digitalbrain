Using each screen

A walk through every screen in the order you would meet them - what it is for, who sees it and the steps to get something done. Menu items appear only when the feature is switched on and your role allows it.

Signing in

  1. Open the address your administrator gave you and enter your user ID and password. This way in always works, with or without Microsoft.
  2. If your company set it up, Sign in with Microsoft is offered too. It only proves who you are; it never grants access by itself.
  3. If you added an authenticator app, enter its six-digit code. Three wrong codes send you back to the password; five failed sign-ins lock the account for 15 minutes.

Sessions end after 30 minutes of inactivity. More on sign-in and the authenticator app.

Overview

Your landing page: the applications you have access to, and Needs attention - a list of things waiting on you, such as a draft graph ready to publish, a published version behind its sources, access reviews due or learned candidates. Each item links to the screen that acts on it.

Onboarding

For an owner setting up an application. At the top is the knowledge cycle (Set up → Feed → Build → Check → Publish → Use) with where you are; below are the gates each feature needs, ticked as they are met: which connectors you use, an AI provider and credential, a repository, a published graph, an approver.

Knowledge → Documents: adding documents

  1. Open Knowledge (or Runbooks) and choose Add. Pick Upload documents, Upload a folder or Import from a link.
  2. Before you upload, the popup says whether the next graph version will be built with AI, and if not, why (AI switched off, no credential, budget spent).
  3. Each file is virus-scanned, then converted to text in an isolated process with no network access. Scanned pages are read by OCR, and the text says which pages were.
  4. The document gets a type, a source check score and a content check. "Ready" needs 80 and no check missing outright. The checks only advise - nothing is ever left out of the graph because of them.
  5. If the personal-data scan flags PHI or PII, decide whether to Restrict it. Restricted sources stay readable by people with access but are never sent to AI or cited.
  6. A new draft graph version is built automatically a few seconds later.
On a document's page you can change its type (your choice always wins over the rules), Ask AI what it is when the rules said Other, request an AI review of clarity and gaps, Convert again (owners, if the original was kept), mark it as rules (owners), restrict it, or delete it.

Knowledge → Code Repos

  1. Choose Add repository → From GitHub (owner/name) or From a folder on this server (only if an operator listed allowed folders; Browse shows them).
  2. Indexing runs in the background and produces a snapshot: files, symbols, routes, imports and calls.
  3. Open a repository for Structure, Reviews (compare a branch, pull request or working changes) and Documentation (reverse-engineered docs). Refresh re-indexes; Retire removes it.

Knowledge → Tickets

Imported tickets with a quality score each (Jira tickets keep their own ticket score). Use it to see what a connector brought in and to start a Code Factory run from a ticket.

Knowledge → Graph, Quality, Versions

  • Graph - explore the published (or any) version: nodes, relationships and the quote behind each. Generate builds a new draft on demand, choosing structure only or a model.
  • Quality - each version charted with and without its AI: questions found, ranking quality, cross-document links, orphans, quoted relationships. Up and down arrows say whether a figure got better or worse than the version before.
  • Versions - every version with its benchmark score and release check. Check and publish runs the checks again: hard failures (a source changed, a quote no longer verifies, a source since restricted) refuse; soft failures (fewer questions found, weaker sources…) publish only with a typed reason, which is kept. The bar at the top is where an owner switches automatic publishing on or off.

Knowledge → Learned

Owners and contributors see candidates waiting: change records, incident learnings, gaps and wrong answers. Accept adds a source (going through the same masking and scanning as an upload) or a benchmark question with the source it should cite; Reject is remembered, so it is not offered again.

Chat

  1. Start a conversation and choose its mode: Source excerpts, AI answer or Graph answer.
  2. Type a question. The answer streams in; Stop ends it and the model call with it.
  3. Click a citation number to see the quoted sentence and open its source.
  4. Wrong answer? under an answer opens a short form; it becomes a candidate in Learned. Questions are shown to owners and contributors without your name.

Everything works with JavaScript switched off: the page simply reloads with the answer instead of streaming it.

Code Factory

  1. Plans: pick a ticket (or write one with New ticket) and choose a repository. If there is no published graph, the form is replaced by the reason.
  2. The run triages, analyses gaps and designs the change. Watch each phase on the run page.
  3. Open the plan. Each item shows its evidence; the rules that apply are shown beside it. Approve, reject items, or send it back.
  4. After approval, Build B writes the work order, implementation, tests and a review, runs pre-write checks, then opens a pull request - or, where allowed, writes into the server folder and can run that folder's tests on an approver's button press.
  5. The run's Tests stage shows the pull request's CI result (or the local test result).

ServiceOps

  1. Incident triage lists incidents imported from ServiceNow (or added with New incident).
  2. Open one to see its neighbourhood: similar incidents, same event, recent changes, linked runbooks and automations.
  3. Press Triage. Steps tick as they run: profile, walk the graph, ask the AI, verify citations, rate the evidence, save.
  4. Record the verdict: choose the actual cause from the brief's citations. Withdrawing it removes the confirmed link.
  5. The Graph tab shows the operations graph; Automations lists automations, with Simulate run, and real execution for owners where a connection allows it.

My access and Account

My access lists every application you can open, your role there and what that role can do. Account → Authenticator app adds or removes your authenticator and shows recovery codes once.

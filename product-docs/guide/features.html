For everyone

What each feature does for you

Each feature in one place: what it gives you, who uses it, what it needs first, and the guardrail that keeps it trustworthy. An owner switches any feature on or off on the Features screen; a feature that is off disappears from the menu.

Knowledge

What it gives you: one library of everything your team wrote down, kept current and checked. Its tabs are Documents · Code Repos · Tickets · Graph · Quality · Versions · Learned.

Who uses it
Everyone reads it. Contributors and owners add and change it. Owners set rules about it.
Ways in
Upload files or a whole folder; import from a link (a web page, a GitHub file or folder, a SharePoint folder); or let a connector import tickets, incidents, knowledge articles and automations.
Files it reads
PDF, Word, Excel, PowerPoint, CSV, Markdown, HTML, text, JSON, XML and more, converted to text. Scanned PDF pages and images (PNG, JPG, TIFF) are read by OCR when it is on; images are refused without it.
What it checks
Every upload is virus-scanned first. Each document is given a type (business requirements, ADR, runbook, postmortem… 20 types plus Other) and two scores - a source check (is it readable, structured, dated, owned?) and a content check against what that type of document should contain.
Personal data
A scan suggests where personal or health data appears (tagged PHI or PII). A person decides whether to restrict a source, which keeps it away from every AI path. An owner can switch on masking, which replaces chosen kinds of value before anything is stored.
Why The converted text is the record: every quote is checked against it. Keeping the original file is a setting (on by default), so a team that must not keep originals can still keep verifiable text.

The knowledge graph and its versions

From the library, Digital Brain builds a graph: the things your sources name (tickets, requirements, controls, components, code, runbooks, incidents, changes) and how they relate (depends on, affects, violates, required by, implemented in, covers, is on, modifies, fixes, deployed to, verifies, references). Every relationship keeps the exact sentence that shows it.

  • Built by rules first - headings, tables and references are read without any AI, for free.
  • Then enriched by AI (unless an owner switched that off) - a model proposes relationships, and only those whose quote is found word for word in the source are kept.
  • Every build is a draft version. The Versions tab shows each one, its benchmark score and its release check. Check and publish makes it the version that answers.
  • Quality shows each version measured with its AI and without it, so you can see what AI added.

Learned

What using the platform teaches comes back here as candidates, never straight into knowledge:

CandidateComes fromIf accepted, becomes
Change recordA Code Factory run delivered after an approved plan, with every check passingA knowledge source
Incident learningA triage verdict that confirmed a cause from triage's own evidenceA knowledge source
GapA complete answer that cited nothingA benchmark question - with the source it should cite
Wrong answerSomeone pressed Wrong answer? on a chat answerA benchmark question - with the source it should cite
Why Accepted questions make the release check harder to pass, so the knowledge gets better the more it is used. Learned sources are never accepted as proof that code meets a requirement - the platform never cites its own output as evidence of itself. Owners and contributors see the questions people asked, without who asked.

Rules

An owner can mark a source - a coding standard, a security design, a control matrix - as rules. Its numbered rules, rule tables and "must / shall / never" lines are read without AI. When someone reviews a Code Factory plan, the rules that clearly apply to that ticket are shown beside it, each quoted from its line. A rule never approves or refuses anything; a person still decides.

Chat

What it gives you: ask a question in plain words and get an answer with numbered citations. The answer streams in as it is written, and Stop really stops it.

Answer modeWhat it doesUses AI?
Source excerptsFinds the best passages in your current sources and shows them, ranked.No - free
AI answerSearches the current sources and has the model write an answer from what it found; the model may search again as it works.Yes
Graph answerAnswers from the latest published graph version (or one you pin), following relationships between sources.Yes

The mode belongs to the conversation, so sending a message never silently changes it. If an answer is wrong, Wrong answer? sends it to the Learned inbox. The Chat API lets another program ask questions with an API token, through the same checks.

Code Graph, Code review and Reverse engineering

Code Graph (under Knowledge → Code Repos) indexes a repository - from GitHub, or from a folder on the server an operator allowed - into files, symbols, routes, imports and calls, and links code to the requirements that name it. Code is not a knowledge source: Chat does not read it.

  • Code review compares a branch, pull request or working changes with the indexed snapshot. Rule-based checks are free: what the change reaches through imports, routes and symbols added or removed, source with no test, requirements that mention it. An AI review runs only when someone presses its button; every finding must quote the diff, a dependent file or a requirement. Nothing is posted to GitHub.
  • Reverse engineering writes documentation from one snapshot - models, routes, components and traceability - with each section labelled read from code, inferred, verified reference or AI-written. It can be added to Knowledge, but is never accepted as evidence that code meets a requirement.

Code Factory

What it gives you: a ticket becomes a reviewed plan, then a prepared change and a pull request (or, on a development or demonstration server, a change written into a local folder).

Who uses it
Contributors and owners start runs; someone with approval rights approves the plan.
Needs first
A published knowledge graph, an indexed repository, an AI provider - Onboarding lists each gate and whether it is met.
Guardrails
A run without a published graph is refused rather than producing a plan that cites nothing. By default one person may approve their own plan (most installations have one operator); a deployment can require a second person, and a self-approved plan says so in the audit record.

ServiceOps

What it gives you: when an incident arrives, a triage brief: similar past incidents, recent changes, the runbook passages that mention the affected component, and ranked hypotheses about the cause - each with checkable evidence.

  1. Profile symptoms - the incident's words, component and service are read.
  2. Walk the graph - the operations graph links incidents, changes, knowledge articles and automations by rules.
  3. Ask the AI - the one paid step: the model proposes causes from that evidence pack.
  4. Verify citations - every quote is checked against its record.
  5. Rate the evidence and save.

A person records the verdict - the actual cause, chosen from the brief's own citations. That confirmed link stays in the graph and can become an incident learning.

Automations

Automations imported from AWX, Rundeck, Azure Automation, ServiceNow flows or a team's list appear in the operations graph, linked to the incidents and runbooks that mention them. Simulate run records exactly what would be sent and sends nothing. Real execution exists for an AWX connection and two built-in platform jobs: an owner only, only job templates on that connection's allow-list, only for an automation whose record still verifies - and, where the connection or the automation requires it, only after a different owner approves. Each request carries a key, so a repeated click never launches twice.

Connectors

Connectors bring in records from other systems and keep them current.

ConnectorBrings inGood to know

GitHubIssues of a repositoryScheduled imports read only what changed

An owner can schedule an import. It runs as the person who created the connector, and stops by itself if that person loses owner access. Status is part of each imported record, so a ticket moving to Done is noticed. Records that disappear from the source are retired only when the owner says the filter is complete.

AI settings and cost reports

Each application chooses its own AI provider (Anthropic Claude or OpenAI), model per task, prices, reply limits and a monthly budget. Every paid call writes a receipt; AI cost reports show spend by task, model and person. See AI, cost and your data.

API and assistants

Any member can issue themselves an API token on Settings → API access. A token acts as the person it belongs to - revoke their access and the token stops working. It reaches graph search, the MCP endpoint (so AI assistants that speak the Model Context Protocol can search your published graph), the Chat API and the triage API. Details: APIs, MCP and SCIM.

AI, cost and your data

Which AI Digital Brain uses, when it spends money, how an owner caps that spending, and what happens to your data on the way to a model.

Which AI, and whose account

Each application chooses its own provider - Anthropic Claude or OpenAI - and its own model for each task. The credential belongs to that application: an owner sets it on Settings → Credentials (or an operator mounts it as a file), and its value is never shown again. One application never uses another's key, so each team's bill is its own.

  • A Claude credential may be an API key or a Claude subscription token made with claude setup-token.
  • Embeddings (finding passages by meaning) use OpenAI only, because Anthropic offers no embeddings service. They switch on only where the application has its own OpenAI key.
  • On a development machine, an operator may let Claude use the developer's own Claude login when an application has no credential. A production server refuses that setting outright.

Why Nothing paid for is paid for twice. Each AI answer about a piece of text is stored under a fingerprint of exactly what the model read, so an unchanged document is never sent again - a rebuild after one source changes costs one call, and the scorecard checks that it stays that way.

The monthly budget

  • An owner sets the cap on AI settings. No cap set means no limit.
  • The cap stops calls from starting. A call already running is never cut off halfway, and a graph build that reaches the cap keeps what it already paid for.
  • Spend is calculated from receipts at the prices an owner entered per model. A model with no price reads as $0 and the Prices table flags it as Not priced - so set prices, or the budget cannot protect you.
  • A missing or unreadable token count from a provider is treated as an error, never as a free call.

Receipts and cost reports

Every paid call writes a receipt: the application, the person, the task, the model, the provider's own request ID and the tokens in and out. AI costs lists them and adds them up. Receipts are kept until a deployment sets a window, which may not be shorter than 400 days, and they outlive even a deleted application so the bill always reconciles.

What happens to your data

Restricted sources never reach AI

Mark a source restricted and it is left out of every AI path - graph builds, search, chat, Code Factory, triage - and taken out of already-published versions at once. People with access can still read it.

Masking before storage

Optional, per application. Chosen kinds of value (health identifiers by default when on) are replaced by a stable placeholder such as [MRN-QZKTWBAF] before the text is stored, so no reader - AI or person - sees the original.

Only what is needed is sent

A model sees the passages chosen for the task, not your library. Code review, document review and reverse engineering send only on a button press.

Nothing a model says is taken on trust

Every quote a model gives is looked up in the source text; anything not found word for word is dropped before it is stored or shown.

Masking is minimization, not de-identification. It replaces only what its rules recognise, and graph versions, chat history and cached AI results written before it was switched on keep what they hold. The AI settings page says both.
